COPY / build context

`Docker COPY failed`，通常先检查三处。

`file not found`、`not found in build context` 和 `failed to compute cache key` 往往不是 Docker 随机坏了，而是构建上下文、相对路径或 `.dockerignore` 之间不一致。

开始排查查看完整诊断流程
最短排查路径

命令中的最后一个参数决定 Docker 能看到什么。

检查 1

实际 build context

`docker build -f docker/Dockerfile .` 的 context 是当前目录 `.`，不是 Dockerfile 所在目录。

检查 2

COPY 相对路径

`COPY` 的源路径相对于 build context，而不是相对于 Dockerfile。不要使用 context 之外的父目录文件。

检查 3

.dockerignore

文件虽然存在，也可能在传给 BuildKit 前被排除。检查目录规则、通配符和例外规则。

可复现示例

先从命令和目录结构验证，不要先删除所有缓存。

确认当前目录

记录执行命令时的位置和末尾 context 参数。

从 context 根目录找文件

检查忽略规则

临时验证具体规则，而不是永久移除 `.dockerignore`。

└── .dockerignore

# Dockerfile 中应从 context 根目录引用
COPY package.json ./
